# 分步开发路线 · 移除「AI 一键分集 + 分镜」

> 目标：把现在「一次点击跑完 7 个阶段」的黑箱，拆成**每步一个人工闸门**的显式流程。
> 约束：不改剧本解析内核（`engine.js`）、不改单步 AI 接口语义；只改编排层与工作区顺序。
> 状态：**S0 / S1 / S2 已完成**（全量回归 17/17 通过），下一步是 S3「分集独立成步」。
> 换机接手请读 `docs/dev-续作任务计划.md`（含环境、代码坐标、坑、分支与未提交事项）。

## 一、已锁定的四项决策

| # | 决策 | 选择 | 直接后果 |
|---|---|---|---|
| D1 | 分集 / 分镜由谁产出 | **两个独立 AI 步骤 + 人工闸门** | 复用已有 `/api/ai/plan`、`/api/ai/storyboard`，前端只做编排 |
| D2 | 上一步改了，下游怎么处理 | **整步作废 + 显式重跑**（但本轮就把 `sceneStableKey`/`shotKeyOf` 写进数据） | `S.stale` 从提示条升级为步骤状态机 |
| D3 | 定妆与分镜谁在前 | **翻转**：剧本 → 分集 → 分镜 → 定妆 → 出片 | `S.step` 3/4 语义对调，十余个验证脚本要同步改 |
| D4 | 分镜产出粒度 | **只有单集闸门**，第一版不给「剩余全部」 | 20 集就点 20 次；杜绝一键换个名字复活 |

### 为什么 D2 要「先用 A，但先埋 B 的键」

`projects/` 下已有 29 个真实项目。若等到要做增量对齐时才引入 `shotKeyOf`，就得迁移全部历史数据；
现在把键写进数据，成本只是加两个函数，后面想做「只重算受影响的镜头」时不用推倒重来。

**本轮的已知缺陷（需接受）**：重算分集或整步重跑分镜，会覆盖手工改过的镜头文字与已排的镜号。
缓解办法是重跑前二次确认，并在确认框里列出「将影响 N 个镜头、其中 M 个你改过」。

## 二、目标工作区模型

```
剧本阶段                          制作阶段
① 改剧本 → ② 分集 → ③ 分镜 → ④ 定妆 →（出片：首帧提示词 / 出图 / 导出）
            ↑闸门     ↑逐集闸门   ↑按镜头定妆
```

| 步 | 工作区 | 唯一产出 | 进入条件 | 闸门 |
|---|---|---|---|---|
| 1 | 改剧本 | 规范场次剧本 `S.script` | — | 规范度五项齐 / 允许带缺陷前进 |
| 2 | 分集 | `S.episodes`（含场次区间） | 剧本非空 | 看过切法并点「确认分集」 |
| 3 | 分镜 | `S.shots`（逐集追加） | 分集已确认 | **每集一个闸门** |
| 4 | 定妆 | `S.assets` 的参考图 | 至少一集有镜头 | 全部资产有图；末段做首帧提示词 / 出图 / 导出 |

> **保持四个工作区**：第 3 步同时承载「分镜表编辑」，「出片」是第 4 步末尾的一组动作，不单独开第 5 个工作区——少一轮脚本改动。
> 顺序变化对照：旧 `1 改剧本 / 2 拆解确认 / 3 资产定妆 / 4 分镜表` → 新 `1 改剧本 / 2 分集 / 3 分镜 / 4 定妆`。即 **3↔4 对调，同时第 2 步职责收窄为只管分集**。

### 阶段 3 · 分集独立成步（第 2 步）

**目标**：分集从「自动附带」变成「可看、可改、可重算」。

**改动**
- `planStep()` 取代 `planOnly()`：**删掉 `studio.js:862` 的 `S.episodes.length` 短路**——这是现在"分集永不重算"的根因。显式由按钮触发。
- 分集表可编辑：改集名、改 `sceneFrom/sceneTo`、拆分/合并、删集。编辑后 `episodes[].source = "manual"`。
- 剧本变更 → `steps.plan.status = "stale"`，第 2 步顶部出条：「剧本改过，现有分集基于旧稿」+ 「重算分集」。
- 重算前二次确认，列出「将覆盖 N 集手调结果」。确认后 `steps.shots.byEp` 全部置 `stale`（D2：整步作废），但**不删 `S.shots`**——只是标红，等你进第 3 步逐集重跑。

**依赖**：阶段 2（步骤号与入口）。
**完成标准**
- 改剧本 → 第 2 步出现 stale 条；点「重算」才发出 `/api/ai/plan`；不点则分集保持原样并显示"基于旧稿"。
- 手改一集场次区间 → 刷新页面仍在（`episodes` 在 `PERSIST_KEYS` 内）。
- 分集变更后，第 3 步所有集标为「需重算」，已生成的镜头仍在表里可见。
- 新脚本 `tools/verify_plan_step.mjs` 覆盖：stale → 重算 → 集数变化 → 第 3 步全部标红。

### 阶段 4 · 分镜逐集闸门（核心）

**目标**：第 3 步按集生成，每集出完即停，失败隔离。

> 便宜的原因：`ai.js:140-148` 的 `storyboard()` **本来就是按集切片**（`ep.sceneFrom..sceneTo` + `E.scriptSlice`），`AI.run` 本来就是 `episodes.forEach` 逐集调用。这一步不是新建架构，只是把循环里的「不停」改成「停」。

**改动**
- 新增 `storyboardStep(epNo)`：只请求一集，返回该集 `shots`。
- 集级状态 `S.steps.shots.byEp[epNo] ∈ idle|running|ready|failed`，第 3 步每个集 tab 上带状态点与按钮（idle→「生成本集」/ ready→「重跑本集」/ failed→「重试」）。
- 合并规则：只替换 `shots[].key` 属于该集的镜头，其它集原样保留；`renumberShots` 后统一重排镜号。
- 失败隔离：单集失败不触碰其它集，不弹全屏遮罩，只在该集卡片上留错误与重试。
- 中断恢复：`S.shots` 落盘；重开页面读 `steps.shots.byEp`，把 `running` 归一为 `failed`。
- **不提供**「全部生成」「剩余全部」按钮（D4）。集数 > 8 时给一行提示「需逐集确认，共 N 集」。

**依赖**：阶段 3（分集必须确定，否则集号漂移）。
**完成标准**
- 3 集示例项目：逐集点 3 次，Network 里是 3 次独立 `ai/storyboard` 请求，每次 payload 只含该集场次。
- 第 3 集故意断网/超时：前两集镜头完整保留，第 3 集显示「重试」。
- 生成第 2 集后重开页面：第 1、2 集 ready，第 3 集 idle，镜号连续无重号。
- 第 3 步 DOM 内不存在任何"全部"语义的生成按钮。
- 新脚本 `tools/verify_shot_gate.mjs` 覆盖上述四条。
